# Privacy policy for Hackatime for Kaggle Notebooks

Effective 9 August 2026

Hackatime for Kaggle Notebooks records coding activity in Kaggle notebook editors and sends WakaTime compatible heartbeats to Hackatime or another HTTPS endpoint selected by the user.

## Data the extension handles

The extension handles the following data only to provide coding activity tracking:

- The API key and HTTPS heartbeat endpoint entered in extension settings
- A random machine identifier generated by the extension
- Kaggle notebook identity, including the Kaggle account name and notebook slug from the edit page URL
- Notebook source while it is open, solely to calculate language, imported package names, notebook-wide line totals and edit metrics
- Coding activity including cursor position, line number, line additions, line deletions, save activity and heartbeat time
- Browser platform and user agent information required by the WakaTime heartbeat format

Notebook source is processed locally. The extension does not include notebook source in heartbeat requests. The extension does not inspect, extract or store Kaggle authentication cookie values and it does not send those cookies to the configured heartbeat endpoint. When requesting notebook content from Kaggle's same-origin Jupyter Contents API, Chrome may automatically include credentials normally used for that Kaggle or Jupyter origin.

## Storage

The API key, selected endpoint, random machine identifier and last heartbeat times are stored in Chrome extension local storage. Current notebook metadata and session throttle times are stored in Chrome extension session storage. This data remains until the user clears extension data or removes the extension.

## Transmission and sharing

Heartbeats are sent directly over HTTPS from the user's browser to the endpoint selected by the user. The default recipient is Hackatime. The user may instead select WakaTime or another WakaTime compatible HTTPS service. The API key is sent only to that endpoint in the request authorisation header.

A heartbeat includes notebook identity, project, language, imported package names, line totals, cursor position, edit metrics, save activity, time, a random machine identifier, browser platform and user agent. The extension has no advertising, analytics or developer-operated intermediary service.

The extension developer does not sell user data. Data is not used for advertising, credit decisions or any purpose unrelated to coding activity tracking. Data sent to the selected endpoint is subject to that service's privacy and retention practices.

## User choices and deletion

The user chooses the heartbeat endpoint and can change the API key or endpoint in extension settings. Access to a custom endpoint is requested only when the user saves it. The user can revoke optional site access in Chrome. Removing the extension or clearing its stored data deletes data retained by the extension. To delete heartbeats already received by a selected endpoint, contact that service.

## Limited use

Use of information by this extension complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. Data is handled only as necessary to provide the extension's stated single purpose.

## Contact
